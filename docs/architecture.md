# 架构：Godot 客户端 + C++ 游戏服务器

## 三条硬约束

**① 规则只有一份实现，在 C++ 里。**

GDScript 不写任何规则。一旦 Godot 侧也实现一遍规则，单机和联机就会慢慢分叉，而卡牌游戏的规则（抽牌顺序、随机数、隐藏信息）是最经不起分叉的东西。

**② `core/` 零依赖。**

不 include Godot，不 include socket。所以同一份静态库能被三处链接：

| 宿主 | 用途 |
|---|---|
| `apps/md_sim` | 批量对局、平衡性回归 |
| `apps/md_server`（待建） | headless 服务器，Linux 上跑 |
| `godot/addons/md_core`（待建） | GDExtension，进 Godot 进程跑单机 |

**③ 单机 = 进程内假服务器，协议与联机完全相同。**

GDExtension 暴露出去的接口，就是网络的接口：

```
submit(json command) -> json
snapshot()           -> json    // 当前座位的 PlayerView
event                    信号   // 事件流
```

于是 Godot 侧只有一份客户端代码，单机和联机的差别只是 transport 换了个实现。

## 数据流

```
单机：
  GDScript UI ──json──> GDExtension ──> md::Session ──PlayerView──> json ──> UI
                                          同一个 core

联机：
  GDScript UI ──tcp/ws──> md_server ──> md::Session ──PlayerView──> 网络 ──> UI
                                          同一个 core
```

## 为什么只暴露 3 个方法，而不是把每种类型都绑进 GDScript

GDExtension 的绑定是手写样板代码，绑定的类型越多，维护成本越高，而且每次改数据结构都要重编译。

回合制卡牌每回合的 payload 只有几 KB，JSON 的性能完全不是瓶颈。所以只绑 3 个方法 + 1 个信号，其余全部走 JSON。

代价是 GDScript 侧少了静态类型。可以接受：这一层是**数据**，不是逻辑。

## 为什么不用 Godot 的 MultiplayerAPI / ENet

Godot 的 high-level multiplayer 把序列化和属性复制交给引擎，它假定"状态是可以同步的节点属性"。但这款游戏的核心恰恰是**按玩家裁剪的隐藏信息**——引擎的复制模型表达不了"这张牌只有 A 看得到"，硬套就得在 GDScript 里手写裁剪逻辑，等于把规则又实现了一遍。

用自定义协议反而更简单：服务器只发 `PlayerView`，客户端根本没有它不该看的数据。

## 进程内 vs 子进程

单机走进程内（GDExtension 直接调 Session）：

- 零网络延迟，存档 / 读档就是序列化 Session 状态
- 调试是单进程，简单
- **注意**：`md::Session` 不是线程安全的，必须固定在 Godot 主线程上调用

联机走独立进程。两者共用同一个 Session。

将来如果想让单机也能开房给朋友加入，把 transport 从进程内换成 `tcp://127.0.0.1` 即可，游戏代码不用动。

## 内容与规则分离

| 层 | 放什么 | 变更频率 |
|---|---|---|
| C++ `core/` | 规则、状态机、随机数、视角裁剪 | 低，改一次要重编译 |
| 数据文件（JSON） | 卡牌定义、身份牌池权重、记忆碎片文本、剧情 | 高，天天改 |
| GDScript / 场景 | UI、演出、音效 | 最高 |

**不要把剧情和卡牌数值写死在 C++ 里**，否则改一句台词都要重编译。目前牌池权重还硬编码在 `identity_weights()` 里，接 GDExtension 之前应该挪进 JSON。

## 服务器分层

```
apps/md_server/main.cpp   socket、select、投递（~250 行，不含任何规则）
        │  Delivery{conn, line}
        ▼
md::net::Room             座位、回合、视角裁剪、掉线转 AI —— 不碰 socket
        │
        ▼
md::Session               规则
```

`Room` 只产出 `Delivery{conn, line}`，它不知道 socket 存在。`md_server` 的唯一职责是把 `line`
写到 `conn` 对应的 fd 上。

**这个拆分不是洁癖**：见下面的环境限制——本机根本跑不了 socket 程序。把 Room 解耦之后，
真正会出错的部分（座位、回合、视角裁剪、掉线接管）仍然可以被完整验证。

## 无网络端到端自检

`apps/md_selftest` 直接驱动 `Room`，26 项断言：

| 用例 | 验证什么 |
|---|---|
| AI 自对局 | 四个 AI 能自行打完一局，且不产生任何真人投递 |
| 单真人 + 三 AI | join → start → 走完整局 → 收到 over |
| **隐藏信息** | 每一份 view 里的手牌张数 == `pub_hand[自己]`，未泄露他人手牌 |
| 非法输入 | 他人回合行动、伪造 `seat`、非法 JSON、未知命令均被拒 |
| 越界下标 | `illegal move` |
| 掉线 | 该座位转 AI，其余人仍能打完 |

其中"伪造 seat"这一条值得强调：**服务器一律以连接自身的座位为准，绝不信任客户端自报的
seat 字段**。少了这一条，任何客户端都能替别人行动。

## 环境限制

这台机器上**任何链接了 `ws2_32` 的可执行文件都会被 Windows Application Control 拦下**。
用一个 30 行的探针确认过：

```
probe_plain.exe   → 正常运行
probe_wsa.exe     → An Application Control policy has blocked this file
```

所以 `md_server.exe` 能编译、能链接，但**不能在本机运行**。要跑起来得换一台机器：

```bash
./build/md_server --port 24680 --seed 1 -v
```

客户端直连 TCP 发换行分隔的 JSON 即可，协议见 `apps/md_server/main.cpp` 顶部注释。

## 当前实测基线（200 局，最大 8 轮，阵营解锁 7 / 身份解锁 9）

| 指标 | 数值 |
|---|---|
| 好人胜 | 66.5% |
| 卧底胜 | 33.5% |
| 平均轮数 | 5.42 |
| 记忆清零死亡 | 0.49 人/局 |
| 枪杀 | 0.61 人/局 |
| 枪在好人手里 | 70% |
| 开枪命中卧底 | 48.8% |
| 全场首次解锁阵营 | 平均第 3.11 轮 |
| 卧底自己察觉身份 | 中位第 3 轮，41.5% 到终局都没察觉 |

复跑：

```bash
g++ -std=c++20 -O2 -I core/include core/src/*.cpp apps/md_sim/main.cpp -o build/md_sim
./build/md_sim 200 1 8 7 9          # 局数 种子 最大轮数 阵营解锁 身份解锁
./build/md_sim 400 1 8 6 9 --csv    # 扫参用，输出单行 CSV
./build/md_sim 1 1 8 7 9 --trace    # 逐动作打印一局
```

## 这次基线暴露的五个问题

**1. 身份解锁（记忆 9）目前是空转的。**

把身份解锁阈值从 8 调到 9 调到 10，胜率**完全不变**（66.0/66.0/66.0）。因为三个好人子身份没有任何机制差异，AI 拿到 `identity_known` 也不改变行为。

要么给子身份独立能力（追捕者可强制验牌、救援者可救人），要么删掉这条解锁。**现在它只是一个数字。**

**2. 41.5% 的卧底到终局都没察觉自己是卧底。**

这符合"卧底也失忆"的设定，但也意味着一部分卧底整局都在帮好人打自己。要观察这个比例是不是太高了。

**3. 35% 的对局打到 8 轮上限，靠"卧底存活即胜"收场。**

这个收尾偏软——玩家会觉得"什么都没发生就输了"。需要一个更有说服力的终局条件。

**4. 枪的命中率是 48.8%，等于抛硬币，但它决定了胜负。**

枪杀 0.61/局 vs 记忆清零 0.49/局，**枪是主要的淘汰手段**。可是开枪的依据只有牌面推断，单薄了点。可以考虑让开枪前必须先有一个"指认"动作，把证据摊到桌面上，让开枪变成一次公开的立场声明。

**5. 好人误判自己是卧底时会打出卧底行为，造成自相残杀。**

阵营阈值从 5 提到 7，好人胜率从 79.5% 掉到 66.0%——因为阈值越低，好人越早确认"我是好人"，越不容易误入卧底打法。

这其实是个很好的机制（**你的误判会变成你的行为**），但说明 AI 的自身信念校准还需要调，也说明玩家会有同样的困惑。
